PRIVACY

Your debugging data stays under your control.

SignalDock is a local-first browser application. Ordinary log, trace, project, case and investigation workflows do not require a SignalDock account, hosted ingestion service or telemetry endpoint.

01

No telemetry endpoint

The production runtime does not include a SignalDock analytics beacon, account API or background upload path for imported log contents.

02

Explicit local input

Files enter through user-initiated selection, drag-and-drop or supported File System Access actions. The application does not continuously scan arbitrary local files.

03

Local browser state

Settings, Saved Views, Query Library data and project metadata can use local browser storage. Recovery snapshots and compatible search-cache data can use IndexedDB.

04

Explicit exports

Portable workspaces, cases, baselines, bundles and reports are created only when you choose a save or export action.

LOCAL STORAGE BOUNDARIES

What may remain on the device.

Local-first does not mean nothing is ever persisted. SignalDock keeps certain state locally so work can be restored or reused without a remote service.

LOCAL

Preferences & reusable views

Settings, Saved Views and Query Library records can remain in browser-local storage until you clear or replace them.

LOCAL

Recovery snapshots

Eligible workspaces can write bounded crash/restart recovery state into IndexedDB, including normalized log-derived content needed to restore that local session.

LOCAL

Search cache

A compatible dataset can have a bucketed IndexedDB candidate-index cache. It is validated against the dataset fingerprint and falls back safely when incompatible.

PERMISSIONED

File handles

Supported browsers can retain local File System Access handles for project reopen workflows. Handle capability keys are stripped from portable project exports.

METADATA

Project records

Projects store local organizational metadata such as names, descriptions and recent artifact references rather than copying imported log files into the project record.

METADATA

Case attachments

Case Workspace attachment entries are metadata-only references. Referenced file bytes are not embedded into the case record.

PORTABLE DATA BOUNDARIES

Different artifacts contain different levels of detail.

SignalDock separates portable analysis state from live browser capabilities so an exported file does not silently carry arbitrary access to files on your machine.

Workspace / .sdsession

Contains portable analysis state used to continue a local session. It does not embed a live File System Access permission.

Case / bundle exports

Case fields, evidence references and explicitly exported investigation data can be included. Attachment references remain metadata-only.

Baseline / .sdbaseline

Contains aggregate service, dependency and trace-set metrics. Raw log records are intentionally not embedded.

Network boundary: the shipped application CSP keeps connect-src 'none'. The bundled website is script-free, loads no external runtime resources and uses the same no-connection policy.

LOCAL-FIRST BY DEFAULT

Inspect locally. Persist knowingly. Export deliberately.

SignalDock minimizes hidden data movement while still making recovery, reuse and portable handoff explicit.
