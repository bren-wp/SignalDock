PRIVACY

Your debugging data stays under your control.

SignalDock is designed as a local-first application. Ordinary log, trace and investigation workflows do not require a SignalDock account or a hosted ingestion service.

01

No telemetry endpoint

The production runtime does not include a SignalDock analytics beacon, account API or background upload path for imported log contents.

02

Explicit local input

Files enter the application through user-initiated actions such as file selection, drag-and-drop or supported local file capabilities.

03

Local browser storage

Features such as recovery state, query libraries and local project metadata may use browser-local storage mechanisms. They are not remote synchronization services.

04

Explicit exports

SignalDock creates portable workspaces, cases, baselines and reports only when you choose an export or save action.

DATA BOUNDARIES

What different artifacts contain.

Portable artifacts are intentionally separated from live browser capabilities so an exported file does not carry access to arbitrary files on your machine.

Portable workspaces and cases

These files contain analysis state needed to continue an investigation. They do not contain live File System Access handles. Case attachment records are metadata-only references.

Baselines and project metadata

Baselines are aggregate summaries rather than raw-log archives. Project records organize local investigation metadata and references without becoming a background upload channel.

Network boundary: the shipped application CSP keeps connect-src 'none', and the static website itself is script-free.

LOCAL-FIRST BY DEFAULT

Inspect locally. Export deliberately.

SignalDock is built to minimize hidden data movement during debugging.
