SECURITY

Small capability surfaces, explicit trust boundaries.

SignalDock keeps privileged browser and storage operations at narrow platform boundaries while analysis controllers receive only the callbacks they need.

01

No application network path

The application CSP uses connect-src 'none'. Production audits reject fetch, XMLHttpRequest, WebSocket and EventSource primitives in runtime JavaScript.

02

Authenticated worker protocol

Background filtering uses a versioned worker protocol with an unpredictable per-session token, allowlisted message types, request/version checks and bounded payload behavior.

03

Bounded local inputs

Import and analysis paths use explicit size or count limits where needed. Case imports are rejected above their safety limit before file contents are read.

04

No generic native bridge

Desktop integration is intentionally narrow. SignalDock does not expose a generic shell, exec, spawn or arbitrary native invoke surface to application controllers.

ASSURANCE

Checks that ship with the project.

The repository runs repeatable quality gates around syntax, regressions, static architecture rules, local HTTP serving and CodeQL analysis.

Architecture assertions

Controller smoke tests verify ownership boundaries and reject direct storage, filesystem, worker or network capability access where it does not belong.

Static production audit

Static checks reject inline CSS/JavaScript, external runtime resources, missing local references and network primitives in production JavaScript.

Dedicated workers: worker messages are authenticated by protocol and session token. SignalDock intentionally does not use a window-style event.origin check for dedicated worker messages.

DEFENSE THROUGH BOUNDARIES

Keep privileged capabilities narrow.

SignalDock favors explicit local actions over generic or ambient authority.
